#### B-01 商业计划书撰写

**适用场景**：创业BP、融资商业计划书、项目立项报告

**提示词内容**：
```
你是一位资深投资人和创业导师，审阅过数百份商业计划书，知道什么样的BP能打动投资人。

请帮我撰写/优化商业计划书：
【项目名称】：[项目名称]
【项目阶段】：[种子期/天使轮/A轮/其他]
【所在行业】：[行业领域]
【商业模式】：[简单描述怎么赚钱]
【团队背景】：[核心团队介绍]
【当前进展】：[项目当前状态，如：已有产品/有用户/只有想法]
【融资需求】：[融资金额、用途、出让股份]
【目标投资人】：[目标投资机构类型]
【BP用途】：[路演/邮件发送/项目申报]

请撰写专业的商业计划书：

1. 【执行摘要（Executive Summary）】
   - 一句话介绍项目
   - 解决什么问题
   - 解决方案
   - 市场规模
   - 商业模式
   - 竞争优势
   - 团队亮点
   - 融资需求
   （注意：这是最重要的部分，要能在30秒内抓住注意力）

2. 【问题与痛点】
   - 目标用户面临的核心问题
   - 问题的严重程度
   - 现有解决方案的不足
   - 为什么现在是解决这个问题的最佳时机？

3. 【解决方案】
   - 产品/服务是什么
   - 核心功能和价值
   - 如何解决用户痛点
   - 产品形态（APP/网站/硬件/服务）
   - 技术壁垒/核心优势

4. 【市场分析】
   - 市场规模（TAM/SAM/SOM）
   - 市场增长趋势
   - 目标用户画像
   - 用户痛点和需求
   - 政策/技术/社会驱动因素

5. 【商业模式】
   - 收入模式（怎么赚钱）
   - 定价策略
   - 成本结构
   - 单位经济模型（Unit Economics）
   - 客户获取成本（CAC）和生命周期价值（LTV）
   - 盈利路径和时间表

6. 【竞争分析】
   - 竞争格局
   - 主要竞争对手分析
   - 我们的差异化优势
   - 竞争壁垒
   - SWOT分析

7. 【运营数据/ traction】
   - 用户数据（用户数、增长率、留存率）
   - 营收数据（GMV、收入、毛利率）
   - 关键指标（DAU/MAU、转化率、复购率）
   - 增长曲线
   - 里程碑达成情况

8. 【增长策略】
   - 用户获取策略
   - 获客渠道
   - 增长飞轮
   - 未来12个月增长计划
   - 扩张路径

9. 【团队介绍】
   - 核心团队成员（姓名、职位、背景）
   - 为什么是这个团队做这件事？
   - 顾问/投资人
   - 组织架构和招聘计划

10. 【财务预测】
    - 未来3-5年财务预测
    - 收入预测
    - 成本预测
    - 关键假设
    - 盈亏平衡点

11. 【融资计划】
    - 融资金额
    - 估值/出让股份
    - 资金用途（分点说明）
    - 里程碑规划
    - 下一轮融资预期

12. 【风险与应对】
    - 主要风险
    - 应对措施
    - 退出路径（可选）

BP撰写原则：
- 简洁有力，15-20页最佳
- 用数据说话，少用形容词
- 突出亮点，先声夺人
- 逻辑清晰，层层递进
- 真诚可信，不夸大不造假

请根据实际情况调整重点，突出项目优势。
```

#### B-02 商业模式画布分析

**适用场景**：商业模式梳理、创业项目验证、商业模式优化

**提示词内容**：
```
你是一位商业模式设计专家，精通商业模式画布和各种商业分析框架。

请帮我分析/设计商业模式：
【项目/产品名称】：[名称]
【所在行业】：[行业]
【当前阶段】：[想法阶段/产品开发中/已上线/成长期]
【现有资源】：[你已有的资源和能力]
【核心产品/服务】：[简要描述]
【目标用户】：[目标用户群体]
【商业模式描述】：[你当前理解的商业模式]
【分析目的】：[验证可行性/优化现有模式/设计新模式]

请用商业模式画布（Business Model Canvas）进行系统分析：

1. 【客户细分（Customer Segments）】
   - 我们为谁创造价值？
   - 谁是我们最重要的客户？
   - 客户群体划分
   - 每个群体的特征和需求

2. 【价值主张（Value Propositions）】
   - 我们为客户创造什么价值？
   - 我们帮客户解决什么问题？
   - 我们满足客户的哪些需求？
   - 我们提供什么样的产品和服务？
   - 为什么客户选择我们而不是别人？

3. 【渠道通路（Channels）】
   - 我们如何接触客户？
   - 通过哪些渠道传递价值主张？
   - 哪些渠道最有效？
   - 渠道如何整合？
   - 获客路径是怎样的？

4. 【客户关系（Customer Relationships）】
   - 我们与客户建立什么样的关系？
   - 如何获取、维护和增长客户？
   - 客户关系如何与商业模式整合？
   - 客户获取成本和维系成本

5. 【收入来源（Revenue Streams）】
   - 客户愿意为什么付费？
   - 收入来源有哪些？
   - 每种收入的占比和增长潜力
   - 定价策略
   - 收入增长的驱动因素

6. 【核心资源（Key Resources）】
   - 我们的价值主张需要哪些核心资源？
   - 我们的渠道、客户关系、收入来源需要哪些资源？
   - 实体资源、知识资源、人力资源、金融资源
   - 哪些是我们独有的、难以复制的？

7. 【关键业务（Key Activities）】
   - 我们的价值主张需要哪些关键业务？
   - 我们的渠道、客户关系、收入来源需要哪些关键业务？
   - 我们的核心竞争力是什么？
   - 哪些业务是必须自己做的？

8. 【重要合作（Key Partnerships）】
   - 谁是我们的重要合作伙伴？
   - 我们从伙伴那里获得什么？
   - 伙伴执行哪些关键业务？
   - 为什么需要合作？
   - 合作模式是什么？

9. 【成本结构（Cost Structure）】
   - 我们商业模式中最重要的成本是什么？
   - 哪些核心资源/业务最贵？
   - 固定成本和可变成本
   - 成本结构是成本驱动还是价值驱动？
   - 规模效应如何？

10. 【商业模式评估】
    - 这个模式的优势是什么？
    - 存在什么问题和风险？
    - 哪些地方最脆弱？
    - 可扩展性如何？
    - 盈利潜力如何？
    - 整体可行性评分（1-10分）

11. 【优化建议】
    - 可以改进的地方
    - 可以增加的收入来源
    - 可以降低的成本
    - 可以强化的优势
    - 优先级排序

12. 【验证计划】
    - 最关键的假设是什么？
    - 如何快速验证这些假设？
    - MVP（最小可行产品）应该包含什么？
    - 验证的指标和时间表

分析原则：
- 客观中立，指出问题
- 结合实际，不空想
- 抓住核心，不贪多求全
- 给出可操作的建议
```

#### B-05 用户调研分析

**适用场景**：用户访谈分析、问卷调查分析、用户需求洞察

**提示词内容**：
```
你是一位用户研究专家，擅长从调研数据中提炼用户洞察。

请帮我分析用户调研数据：
【调研目的】：[为什么做这次调研]
【调研方法】：[用户访谈/问卷调查/可用性测试/焦点小组]
【调研对象】：[目标用户画像]
【样本数量】：[多少个用户/份问卷]
【调研数据/记录】：
[粘贴调研记录、访谈纪要、问卷结果等]
【核心问题】：[最想通过调研了解什么]

请进行专业的用户调研分析：

1. 【调研概况】
   - 调研背景和目的
   - 调研方法说明
   - 样本构成
   - 调研过程
   - 数据质量评估

2. 【用户画像提炼】
   
   典型用户画像1：
   - 基本特征
   - 行为特征
   - 需求和痛点
   - 态度和观点
   - 代表语录
   
   典型用户画像2：
   - ...
   
   用户分群：
   - 可以分成几类用户？
   - 每类的特征和占比
   - 差异点和共同点

3. 【需求分析】
   
   显性需求：
   - 用户明确说出来的需求
   - 需求强度排序
   
   隐性需求：
   - 用户没说出来但实际存在的需求
   - 如何发现的？
   - 需求强度
   
   伪需求：
   - 表面说需要但实际不重要的需求
   - 为什么是伪需求？
   
   需求优先级矩阵：
```

#### B-08 MVP 设计与验证

**适用场景**：最小可行产品设计、创业项目验证、新功能快速验证

**提示词内容**：
```

【用户痛点】：[用户面临的问题]
【我的解决方案】：[你打算怎么解决]
【假设/猜想】：[你认为会成立但还没验证的假设]
【当前阶段】：[只有想法/已有原型/做过一些验证]
【可用资源】：[时间、预算、人力]
【验证目标】：[想验证什么，达到什么标准就算成功]

请帮我设计MVP和验证方案：

1. 【核心假设识别】
   
   最关键的假设是什么？（如果这个假设不成立，整个项目就不成立）
   
   价值假设：
   - 假设1：用户真的有这个痛点
   - 假设2：用户愿意为这个解决方案付费/买单
   - 假设3：...
   
   增长假设：
   - 假设1：用户获取成本是可接受的
   - 假设2：用户会自发传播
   - 假设3：...
   
   按重要性和不确定性排序：
   | 假设 | 重要程度 | 不确定程度 | 优先级 |
   |------|----------|------------|--------|
   | 假设1 | 高/中/低 | 高/中/低 | P0/P1/P2 |

   MVP目标：验证哪个核心假设？

   - 最小可行产品应该包含什么？
   - 什么是必须有的？
   - 什么是可以没有的？
   - 什么是绝对不能加的？

   - 产品原型（Figma/原型图）
   - 落地页/预售页
   - Wizard of Oz（人工模拟）
   - 众筹/预售
   -  concierge MVP（人工服务）
   - 简化版产品
   - 单个功能MVP
   - 其他形式
   
   推荐的MVP形态及理由：

3. 【MVP功能范围】
   
   ✅ 必须包含（Must have）：
   - 功能1
   - 功能2
   - ...
   
   ⚠️ 应该包含（Should have）：
   - 功能1
   - ...
   
   ❌ 这次不做（Won't have）：
   - 功能1
   - 功能2
   - ...
   
   为什么这些可以不做？

4. 【验证指标】
   
   核心验证指标（North Star Metric）：
   - 指标名称：
   - 定义：
   - 成功标准：达到XX就算验证通过
   
   辅助指标：
   - 指标1：定义+成功标准
   - 指标2：定义+成功标准
   - ...
   
   虚荣指标（Vanity Metrics）提醒：
   - 这些指标看着好看但说明不了问题
   - 不要被这些指标误导

5. 【验证方法与流程】
   
   验证步骤：
   1. 第一步：做什么？怎么做？多长时间？
   2. 第二步：做什么？怎么做？多长时间？
   3. 第三步：做什么？怎么做？多长时间？
   
   用户获取：
   - 从哪里找第一批用户？
   - 需要多少用户参与验证？
   - 如何筛选目标用户？
   
   数据收集：
   - 定量数据：通过什么方式收集？
   - 定性数据：通过什么方式收集？
   - 用户访谈计划

6. 【验证时间表】
   
   | 阶段 | 时间 | 目标 | 产出 | 验证指标 |
   |------|------|------|------|----------|
   | 准备期 | | | | |
   | 验证期 | | | | |
   | 分析期 | | | | |
   | 决策期 | | | | |

7. 【用户访谈提纲】
   
   访谈对象：
   
   访谈问题：
   - 开场问题
   - 痛点问题
   - 当前解决方案
   - 对产品的反馈
   - 付费意愿
   - 其他问题
   
   访谈注意事项：

8. 【验证结果判断】
   
   成功标准：
   - 达到什么指标算验证成功？
   - 成功后下一步做什么？
   
   失败标准：
   - 什么情况算验证失败？
   - 失败了怎么办？
   - 是放弃还是调整？
   
   不确定的情况：
   - 什么情况下需要更多验证？
   - 如何进一步验证？

9. 【常见陷阱】
   - 陷阱1：做得太多太完美
   - 陷阱2：只听好听的
   - 陷阱3：自欺欺人
   - 陷阱4：验证方式不对
   - 如何避免这些陷阱？

10. 【如果验证成功，下一步】
    - 产品迭代方向
    - 下一步验证什么？
    - 资源需求
    - 增长计划

MVP原则：
- 最小化：用最少的投入验证最关键的假设
- 快速：越快越好，时间就是成本
- 聚焦：一次只验证一个核心假设
- 诚实：对结果诚实，不自欺欺人
- 学习：无论成败，最重要的是学到了什么
```
